## 六、AI REST API

新增 `/api/ai/*` 15 个端点，与前端 `/api/memo/*` 完全隔离，**前端零改动**。

双通道鉴权：`current_user()` 统一 Cookie 会话（前端）与 Bearer Token（AI/MCP）两种身份。

| 能力 | 实现要点 |
|------|---------|
| 自然语言建日程 | 规则式解析（不依赖外部模型）：日期/时间/时长/优先级/重复/标签 6 类 |
| 解析可预览 | `POST /api/ai/parse` 只解析不落库，返回 `matched` 命中片段 |
| 不臆造 | 无法确定时间返回 **422 `need_time`** + 可执行 hint，绝不默认填充 |
| 幂等 | `Idempotency-Key` 头，同 key 返回首次结果（`idempotent: true`） |
| 批量 | `/api/ai/events/batch` ≤50 条，逐条成败，部分失败不影响整体 |
| 摘要直引 | `/api/ai/brief` 返回已成句的 `summary`，避免模型自己算错统计 |
| 自描述 | `GET /api/ai/schema` 返回全部端点与语法，模型无需外部文档 |
| Token 安全 | 只存 SHA-256；记录 `last_used` / `use_count`；可吊销，吊销后 401 |

**解析回归（12 组用例全通过）**

| 输入 | 解析结果 |
|------|---------|
| 明天下午3点开会 2小时 #项目A 紧急 | 2026-10-29 15:00~17:00 · high · 项目A |
| 下周三上午10点半 评审会 | 2026-11-04 10:30~11:30 |
| 后天 45分钟 站会 每天 | 2026-10-30 09:00~09:45 · day |
| 11月5日 晚上八点 聚餐 | 2026-11-05 20:00~21:00 |
| 周五 15:30 汇报 #汇报 | 2026-10-30 15:30~16:30 · 汇报 |
| 本月30号 交报告 | 2026-10-30 09:00~10:00 |
| 下下周一 培训 | 2026-11-09 09:00~10:00 |
| 半小时后 喝水 | 30 分钟时长，标题无「后」残留 |

过程中修掉 2 个真实 bug：
1. **「下周三」多推一周**（`ahead += 7` 叠加）→ 改为按自然周 `周一 + n×7 + 星期偏移` 计算
2. **只给日期时用当前时分**（「后天45分钟站会」被塞到 22:16）→ 改为默认 09:00

## 七、MCP Server

基于 `mcp` SDK v2（`MCPServer`），**15 个工具**，支持 stdio 与 Streamable HTTP 双传输。

| 传输 | 入口 | 鉴权 |
|------|------|------|
| stdio | `python mcp_server.py` | 环境变量 `MEMO_TOKEN` 或 `--token` |
| HTTP | `http://127.0.0.1:8000/mcp` | **请求头** `Authorization: Bearer <token>` |

HTTP 模式可按请求头取 Token，因此**一个 MCP 服务可同时服务多个不同账号的客户端**。

工具：`create_event` / `create_events_batch` / `update_event` / `complete_event` /
`delete_event` / `toggle_subtask` / `brief_status` / `list_events` / `get_event` /
`get_agenda` / `parse_text` / `list_tags` / `create_tag` / `get_calendar_month` / `whoami`

**端到端测试（真实 MCP 协议，非函数直调）**

| 套件 | 结果 |
|------|------|
| stdio（`tests_mcp.py`） | **16/16 通过** |
| HTTP（`tests_mcp_http.py`） | **7/7 通过** |

期间修掉 2 个真实缺陷：
1. **HTTP 模式身份丢失**：MCP 进程只认启动时的静态绑定 → 改为工具注入 `Context`，从请求头解析 Token
2. **`Context` 未导入致模块加载失败**：表现为 `/mcp` 返回 404（服务根本没起来）→ 补导入后恢复

## 八、架构说明（为什么不是单进程挂载）

Flask 是 **WSGI**，MCP 的 Streamable HTTP 是 **ASGI**，两者不能直接互相 `mount`。
因此 `serve.py` 采用**前置路由**：`/mcp*` 转发给内部 uvicorn（随机回环端口），
其余交 waitress。对外只暴露 **一个端口**，客户端只需记住
`http://127.0.0.1:8000/mcp`。

# 第三轮：修复缺陷 + 同步原站改版

## 十一、本轮修复的缺陷（全部有实测证据）

### 1. 🔴 MCP 并发身份串号（严重）

**现象**：两个账号的 Token 并发调用 MCP HTTP，16 次中有 **6 次串号** ——
A 账号的请求返回了小马的身份，B 账号的操作落到了别人名下。

**根因**：`mcp_server.py` 用模块级全局变量 `_CTX` 传递 MCP Context，
HTTP 模式下多个客户端并发时互相覆盖。

**修复**：改用 `contextvars.ContextVar`，天然按协程隔离。

**验证**（`tests_concurrency.py`）：并发 20 次 → **串号 0 次**（修复前 6/16）。

### 2. 🔴 Token scope 只记录不校验

**现象**：签发 `scope=read` 的只读 Token 后，仍可创建/删除日程、改标签。
**修复**：`ai_user(need_write=True)` 与 MCP `_uid(need_write=True)` 双重校验，
只读 Token 的写操作返回 **403 `read_only_token`**。
**验证**：只读 Token 的 GET 全部 200，POST/PATCH/DELETE 全部 403；读写 Token 正常。

### 3. 🟡 上传白名单形同虚设

**现象**：`PROOF_EXTS` 定义了却从未使用，任意文件（如 `.exe`）都会被存成 `.jpg`。
**修复**：扩展名白名单 + **文件头校验**（`is_image_magic`，认 PNG/JPEG/GIF/WEBP）。
**验证**：`.exe` → 拒；伪造内容的 `fake.jpg` → 拒；真 PNG → 通过。

### 4. 🟡 幂等键跨用户冲突

**现象**：`idempotency` 表以裸 key 为主键，两个用户用相同 `Idempotency-Key`
时，**B 会拿到 A 的创建结果**（严重数据串号）。
**修复**：key 改为 `{uid}:{key}`，并加 24h TTL 清理。
**验证**：两账号同 key 各自创建独立记录；同账号重放仍返回首次结果。

### 5. 🟡 无全局异常兜底

**现象**：未捕获异常 / 404 / 405 返回 HTML，前端会提示「接口返回异常」，
AI 客户端 JSON 解析失败。
**修复**：统一 errorhandler（404/405/413/sqlite.Error/Exception），按路径返回对应 JSON 结构。
**验证**：`/api/ai/*` 与 `/api/memo/*` 的错误均返回 `application/json`。

### 6. 🟡 枚举值无校验污染数据

**现象**：`level=urgent`、`repeat=yearly` 会直接写库。
**修复**：REST 与 MCP 双侧校验，非法值返回 422；空 `level` 落库前兜底为 `middle`。
**验证**：`invalid_level` / `invalid_repeat` / title 超长均被拒。

### 7. 🟡 MCP 无 Token 也能握手

**现象**：无凭据的客户端能完成 initialize 并列出工具，直到调用工具才失败，排查成本高。
**修复**：`serve.py` 前置路由对 `/mcp` 做握手级鉴权，无有效 Token 直接 **401**。
**验证**：无 Token / 伪造 Token / 已吊销 Token → 均 401。

### 8. 🟡 登录锁定把主人锁在门外

**现象**：连错 5 次后，**正确密码也被拒 15 分钟**。
**修复**：锁定期内仍校验密码，密码正确即解锁放行。
**验证**：6 次错误后，正确密码仍登录成功。

### 9. 🟡 进程内共享状态无锁

**现象**：`LOGIN_FAIL` 在 waitress 多线程下非原子读写。
**修复**：`threading.Lock` 保护；`MCPForwarder` Token 校验加 60s 缓存 + 吊销即失效钩子。
**验证**：吊销后立即 401（缓存已被钩子清除），无 60 秒延迟窗口。

### 10. 🟡 分页越界误导模型

**现象**：`page=9999` 返回空列表且 `page` 仍回报 9999，模型会误读为「没有数据」。
**修复**：归一到最后一页并返回 `pageAdjusted` 提示。
**验证**：`page=9999` → 返回实际页 + 中文 hint。

## 十六、复杂重复规则（新增能力）

### 规则语法

| 写法 | 含义 |
|------|------|
| `day` / `week` / `month` | 每天 / 每周 / 每月（月末自动收敛：1/31 → 2/28） |
| `day\|interval:3` | 每 3 天 |
| `week\|interval:2` | 每两周 |
| `complex\|monthly\|2\|2` | 每月第 2 个星期 2（0=周一） |
| `complex\|monthly\|last\|4` | 每月最后一个星期五 |
| `complex\|monthly\|nth:1\|weekday:0` | 每月第 1 个星期一（命名参数等价写法） |

### 验证结果

| 输入 | 下一条 | 是否正确 |
|------|--------|---------|
| 2026-10-28 `week\|interval:2` | 2026-11-11 | ✅ 恰好 +14 天 |
| 2026-01-31 `month` | 2026-02-28 | ✅ 月末收敛 |
| 2026-10-28 `complex\|monthly\|2\|2` | 2026-11-11（第2个周三） | ✅ |
| 2026-10-28 `complex\|monthly\|last\|4` | 2026-11-27（最后周五） | ✅ |
| 2026-10-28 `complex\|monthly\|nth:1\|weekday:0` | 2026-11-02（第1个周一） | ✅ |

端到端：完成 10-28「最后周五」任务 → 自动生成 **11-27**；再完成 → **12-25**，连续正确。

### 非法规则校验（`validate_rule`）

| 输入 | 结果 |
|------|------|
| `yearly` | 重复规则只能是 day / week / month / complex |
| `week\|interval:999` | interval 需为 1~365 的整数 |
| `complex\|monthly\|2\|9` | 星期参数需为 0~6 |
| `complex\|monthly\|9\|2` | 「第几个」需为 1~5 |
| `complex\|bogus` | 无法识别的规则参数：bogus |

### 三端贯通

- **Web**：选中「复杂规则」后出现「第几个 + 星期几」两个下拉，提示文案实时更新（"即在每月最后一个星期五再生成一条"）；编辑时正确回填
- **AI API**：`repeat` 字段接受带参规则，非法值返回 `422 invalid_repeat`
- **MCP**：`create_event(repeat="complex|monthly|last|4")` 同样生效
